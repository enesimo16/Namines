# Namines — Known Unresolved Issues & Open Questions

- **FK relations only populate correctly for PostgreSQL** in `dbintrospect` — the third-phase fix used `pg_catalog` and was PostgreSQL-specific. MSSQL, MySQL, MariaDB, Oracle, and SQLite still return an empty `relations: []`. This blocks full functionality of Desk's canvas view (`namines_desk/03-CANVAS.md`) and any cross-engine introspection feature for those five engines.
- **`UsageEvent` has no `ProjectId` field** — this blocks any per-project billing or usage analytics, both for Desk's planned Analytics screen and for general observability. Fixing it requires a schema migration that "touches the billing path," which is explicitly flagged as a decision Desk cannot make on its own.
- **`GatewayAuditEntry` records writes only, never reads** — by deliberate design (to avoid audit-table bloat from high-volume read traffic), but this means Desk's "Logs" and "Analytics" screens must never claim to show "all requests" — documented as an honesty/wording requirement rather than a bug to fix.
- **Username/project-slug uniqueness in URLs has not been validated** — `services/desk/README.md`'s "kapsam dışı" (out of scope) section explicitly notes the `/{username}/{project}` route is deferred "until username uniqueness in the URL is guaranteed."
- **Stripe price IDs have not been created** (🔴 flagged urgent) — payment code is fully written and tested, but literally zero revenue is possible until 4 Stripe price IDs exist in the live Stripe dashboard.
- **Groq is a single point of failure** for the AI layer — a previously-configured Groq model once started returning "model does not exist," breaking schema generation product-wide (this incident directly motivated the NAI model-naming abstraction). Separately, Groq's free-tier TPM (tokens-per-minute) wall (~6,000 TPM) has repeatedly blocked live end-to-end testing even when daily quota remained. Moving to Groq's paid "Developer tier" (10× TPM, 25% cheaper, requires a card on file) is the recommended fix over switching AI providers entirely — DeepSeek was evaluated and priced out as strictly worse for this specific workload.
- **GitHub App credentials are missing** — this blocks Namines Bot from ever actually writing a comment to a pull request (code is complete as of gate G43) and also blocks Desk's planned GitHub-push deployment feature. Same root blocker for both.
- **Disk space has repeatedly been critical** (🔴, the C: drive was measured down to 3.8GB at one point) — this has caused Docker containers and the control-DB container to crash mid-session. The WSL2 VHDX file does not auto-shrink, which compounds the problem.
- **The developer's home directory (`C:\Users\Enes Yel`) is itself a stray git repository** pointed at an unrelated remote (`automated-recruitment-pipeline`) — flagged repeatedly across sessions as a real risk (a careless `git add -A` run from that directory could attempt to commit the entire home folder). Never fixed as of the last check.
- **Payment infrastructure for Turkey is unresolved** — Stripe has known limitations operating in Turkey; Paddle and LemonSqueezy (both Merchant-of-Record providers) are under evaluation as alternatives but no decision has been made.
- **UI/UX audit findings not fully resolved** (`UI_UX_PRODUCT_AUDIT.md`):
  - 41 uses of `outline-none` vs. only 10 uses of `focus-visible` (partially fixed since the audit).
  - 143 separate `showToast(` call sites — documented as a pattern smell, not reduced.
  - 0 skeleton loaders vs. 83 spinners across the app.
  - Roughly 414 arbitrary `text-[10px]`/`text-[11px]` Tailwind classes still pending migration to design tokens (75 sub-10px instances were already fixed to a `text-micro` token).
  - `components/ui/Button` and `components/ui/Container` primitives exist in the codebase but **zero files actually use them** — 286 buttons across the app are still hand-rolled. A documented "built but unadopted" gap.
- **MySQL 5.7-era syntax compatibility for shared-hosting export is not truly solved** — only a warning comment is appended for CHECK constraints (second-phase doc 13); there is no real version-aware DDL generation in the type system yet.
- **Composite primary keys make Desk's Data-CRUD screen read-only by design** — the Gateway's `update`/`delete` endpoints only accept a single `pkColumn`, so showing a composite-PK table as editable would risk silently updating the wrong row. This is a documented limitation, not an oversight to be fixed casually.
- **The Team plan's "downgrade to Pro" edge case is unresolved** — what happens to the 3rd/extra seat's data and access is an open design question in second-phase doc `01-SIRADAKI-ISLER.md` §4, leaning toward "access becomes read-only, data stays" but not decided.
- **Desk v1's live collaboration/notification feature is only partially scoped**: a polling-based "your schema changed" version-bump banner is in scope for v1, but actually pushing that change through to the live database ("pushla direkt buradaki değişsin") is explicitly **not** part of v1 — it is gated on Namines Vault existing first.
